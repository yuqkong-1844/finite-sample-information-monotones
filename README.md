# Lean formalization of the paper's main results

This directory is a self-contained Lean 4 source package for the paper's main
results in all three dimension regimes.  The machine-checked entry point is
`PaperProofs.lean`.

## Verified results

For `n > m`, the package proves the asymmetric vanishing theorem for a `C¹`
function on an open neighborhood of the probability simplex.  It also proves
that the outer-product formulation of rank-one vanishing is equivalent, on the
simplex, to vanishing on every matrix of rank at most one.  In the polynomial
case it constructs the factorization

```text
P = (tau - 1) * Q.
```

For `n = m`, it proves the determinant-square identity

```text
P = det^2 * Q + (tau - 1) * K
```

and the lower bound `2 * n <= P.totalDegree` when the polynomial is nonzero at
some simplex point.  It also proves the constant-compensation result: for every
row-symmetric polynomial `P`, some nonnegative `M` makes

```text
U ↦ det(U)^2 * (P(U) + M)
```

satisfy the full one-sided data-processing inequality.  The formalization
defines the paper's normalized-defect supremum `compensationSup P`, proves its
defining set is bounded above, and proves that every
`M >= max 0 (compensationSup P)` works.

For `2 <= n < m`, it proves

```text
P ∈ I_n^2 ⊔ Ideal.span {tau - 1},
```

where `I_n` is the ideal generated by the maximal minors of the generic
`n × m` matrix.  It also proves the corresponding lower bound
`2 * n <= P.totalDegree`.  The determinantal algebra is formalized internally:
the generic maximal-minor ideal is prime, every positive power is primary, and
the square is therefore primary.  These facts remove the Schur-chart pivot
factor and make the wide theorem unconditional.

The package also verifies the algebraic reduction behind the paper's DPI
recognition hardness result.  For

```text
F_A(U) = det(U)^2 * c(U)^T A c(U),
```

it constructs the corresponding multivariate polynomial and proves, for
`2 <= n`, that `F_A` satisfies DPI if and only if `A` is copositive.  The same
theorem is exported for rational input matrices.  The restricted family is
also proved row-symmetric and rank-at-most-one vanishing on the simplex.

The final complexity-theoretic wrapper is deliberately not claimed as a Lean
theorem.  Mathlib 4.32 has general computability and Turing-machine libraries,
but it does not provide the required combined infrastructure: a rational
arithmetic-circuit input language with size/cost semantics, the class `coNP`
and polynomial-time many-one hardness in the needed form, or a machine-checked
Murty--Kabadi theorem that strong rational copositive-cone membership is
coNP-complete.  `CopositiveDPIRecognition.lean` therefore proves the complete
semantic reduction without adding an axiom for that external complexity
result.

Finally, `FrobeniusDependence.lean` verifies the squared Frobenius dependence
functional.  It proves that the functional vanishes exactly when a simplex
matrix has rank one, proves covariance equivariance, and proves DPI for

```text
conv (DS_n ∪ R1_n).
```

The file proves that this literal convex hull equals its Lean-friendly witness
form `lambda * D + (1 - lambda) * R`, and it verifies by exact rational
arithmetic the paper's `4 x 3` counterexample to unrestricted DPI.

The source files contain no proof placeholders, user-declared axioms, or unsafe
shortcuts.  The final `#print axioms` commands report only `propext`,
`Classical.choice`, and `Quot.sound`, which are standard Lean foundations used
by mathlib.

## Reproducing the build

The project is pinned to Lean `v4.32.0` and mathlib `v4.32.0`.  Install Lean via
`elan`, open a terminal in this directory, and run:

```bash
lake update
lake exe cache get
lake build
lake env lean PaperProofs.lean
```

The first two commands download the pinned dependencies and precompiled mathlib
cache.  A successful verification ends with exit code `0`.  The printed theorem
types and axiom reports are informational output.

To audit all Lean sources for proof placeholders or shortcuts, run:

```bash
rg -n '\b(sorry|admit|axiom|unsafe)\b' --glob '*.lean' .
```

The command should print nothing.

## Reading the proof

Start with `PaperProofs.lean`, which lists every paper-facing endpoint.

- `GeneralAsymmetricC1.lean` and `AsymmetricPolynomialCorollary.lean` contain
  the asymmetric analytic theorem and its polynomial corollary.
- `SquareSimplexTheorem.lean` and `SquareDegreeBound.lean` are the square-case
  rigidity endpoints.  `ConstantCompensation.lean` proves the square-case
  constant-compensation theorem by elementary finite probability estimates and
  polynomial bounds, without compactness or Taylor expansion.
- `WideSimplexTheorem.lean` is the wide-case endpoint.  Reading its imports
  backwards leads through the local Schur calculation, pivot saturation, and
  the straightening/primaryness algebra.
- `CopositiveDPIRecognition.lean` contains the semantic copositivity-to-DPI
  recognition reduction and the explicit rational-coefficient polynomials.
- `FrobeniusDependence.lean` contains independence-faithfulness, the convex
  restricted-channel DPI theorem, and the exact full-DPI counterexample.

For the wide algebra, the central exported declarations are:

```lean
WidePolynomial.maximalMinorIdeal_isPrime
WidePolynomial.maximalMinorIdeal_sq_isPrimary
WidePolynomial.wide_simplex_maximalMinor_sq
WidePolynomial.wide_simplex_totalDegree_lower_bound
```

The constant-compensation endpoints are:

```lean
SquarePolynomial.compensationRatioSet_bddAbove
SquarePolynomial.compensatedEval_dpi_of_compensationSup_le
SquarePolynomial.exists_constantCompensation_dpi
```

The recognition and Frobenius-dependence endpoints are:

```lean
CopositiveDPIRecognition.rationalRecognitionPoly_dpi_iff_copositive
CopositiveDPIRecognition.recognitionPoly_rowSymmetricOnSimplex
CopositiveDPIRecognition.recognitionPoly_rankOneVanishing
FrobeniusDependence.restrictedChannel_iff_mem_convexHull
FrobeniusDependence.fdi_eq_zero_iff_rank_eq_one
FrobeniusDependence.fdi_convexHull_dpi
FrobeniusDependence.fdi_not_full_dpi
```

## Manual checking in VS Code

VS Code is optional but convenient for inspecting proof states.

1. Install the official **Lean 4** extension (`leanprover.lean4`).
2. Open this directory with **File → Open Folder**.
3. Open `PaperProofs.lean` and wait for the Lean status indicator to become
   ready.
4. Cmd-click a theorem name to jump to its proof.  Place the cursor inside a
   tactic block to see the current goal in the Lean Infoview.
5. Run `lake build` in VS Code's integrated terminal.  Exit code `0` and no red
   diagnostics mean that Lean's kernel accepted the complete dependency graph.

The committed `lean-toolchain`, `lakefile.toml`, and `lake-manifest.json` pin the
compiler and dependency versions.  Readers should leave these files unchanged
when reproducing the results.
